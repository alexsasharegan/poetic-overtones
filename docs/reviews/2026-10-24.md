## Part 1. Decisions that block work

Ordered by how much each one unblocks.

### DEC-4. Scope of marks for the MVP (blocks MRK-1 to MRK-4, CT-3, the meter strip)

*Marks* are things the CSS channels cannot draw: text or a badge above or below a span, a strip per line (the
community scheme's meter strip), and arcs between members of a relation (R-05). They need a design before
anyone builds them. Spec: `spec/app.md` Q18 and Y-03 ("Box (later)").

| Option | What is in the MVP | Cost |
|---|---|---|
| A | None. Text and box styles only. | Cheapest; the community theme stays without its meter strip |
| B | Text above or below a span, and the line strip. Arcs later. | Covers the community meter strip; arcs (the old scansion page's best feature) wait |
| C | B plus relation arcs | Largest; MRK-4 depends on all the rest |

**Recommendation: B.** It closes the main gap in the community theme and keeps arcs, the hardest part to print
correctly, out of the first cut. After your answer the next step is MRK-1, the marks spec.

### DEC-1. Credit wording and the author's confirmation (blocks CT-1 and sharing the community theme)

Two parts, both needing the author of *Phonetic Markup for Verse*:

1. **Credit wording.** Until agreed, no name is written in committed files (AGENTS.md, ADR-0005).
2. **Confirm two sets of choices I made** where the deck contradicts itself:
   - M11: seven colours settled by swatch and place logic: /ŋ/ /hw/ /w/ /l/ /ɾ/ /j/ /h/ (`themes/README.md`).
     Four of the deck's labels look copied from the next column.
   - M12: secondary stress is bold italic (slide 3, the stress slide), not italic (slide 4).

Only you can do this: it is a question to the author. **Recommendation:** ask them both at once, with the
`themes/README.md` colour table attached. If the author is slow to answer, nothing else on the board waits for
it except CT-1.

### DEC-2. Sound tag names (blocks CT-2; costly to change after files exist)

Documents marked for the community theme use tags such as `sound:ng`. Changing the names later breaks every
such file. Spec: `spec/app.md` Q16 (M10).

| Option | Example | Notes |
|---|---|---|
| ARPAbet-like (now) | `sound:ng`, `sound:aa` | ASCII, documented in `themes/README.md`; the table is already written |
| Shavian letter names | `sound:peep` | Fits Shavian, but ties a generic tool to one script |
| IPA spelled out | `sound:eng` | Longer; no standard to follow |

**Recommendation: keep ARPAbet-like.** The tool is generic (ADR-0003), and the names are only tags. A Shavian
mode can add a second tag set (`shavian:peep`) beside them without renaming anything.

### DEC-3. Ids across sessions (blocks CORE-3)

S-04 says ids are "never reused". The editor never reuses an id within a session, but a deleted id is not in
the saved file, so a later session could reuse it. Spec: `spec/app.md` Q17, S-04 (M7).

| Option | Effect |
|---|---|
| Soften S-04 to "unique in the document" | No file change; ids stay opaque and simple |
| Record retired ids in the file | S-04 holds exactly; the file grows a list that nothing else uses |

**Recommendation: soften.** Ids are opaque and wired only inside one file (S-04, B-10). Nothing outside the
file refers to them, so reuse after deletion causes no harm.

### DEC-7. Playwright as a dev-only dependency (blocks QA-1)

The painter and app are checked only by ad hoc headless-browser scripts that are not in `npm test`. ADR-0012
forbids runtime dependencies only. **Recommendation: yes.** Dev-only, with the runtime staying
dependency-free. This is the best protection for the most visible code.

### DEC-5. Export of `<style src>` (blocks CORE-4)

Today export writes the CSS inline, so an exported file stands alone and the `src` link is lost (M5, I-02).
Spec: `spec/app.md` Q19. **Recommendation: keep inline.** It matters only once people share themes as files.

### DEC-11 (new, proposed). The busy display for a fresh standard tier

A new standard tier is all unconfirmed, and the Reader theme outlines every unconfirmed member. A new word
tier draws a dashed box round every word. It is not on the board yet; if you agree, I add it as DEC-11.

| Option | Effect |
|---|---|
| Themes style `member[inferred]` more quietly | Fix lives in the themes; inferred labels stay visible (ADR-0004) |
| A new standard tier starts hidden | Quiet by default; the reader must switch it on |

**Recommendation: the first.** Showing the difference between inferred and confirmed is a core rule
(ADR-0004), and hiding the tier works against it. A dotted underline or a lighter outline is enough.

## Part 5. Risks I know of

* **Renderer tests are manual** (see DEC-7).
* **Speed on long texts.** Every edit takes a full snapshot for undo and repaints everything. Fine for poems;
  too slow near the 1,000,000 code point limit (CORE-6).
* **Two loaders to keep in step.** `check.py` and `src/core/load.js` must agree, rule for rule.
* **Accessibility** (Q20, RND-3).
* **Older prototypes.** `prototypes/layers/` and `scansion.html` duplicate parts of `src/` (QA-2).
* **Housekeeping.** A renamed folder needed deletion permission for git to clean up after commits. A future
  session may need to ask again.
